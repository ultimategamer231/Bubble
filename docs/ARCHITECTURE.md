# Architecture & Timer Reliability

Technical authority. Changes require a `DECISIONS.md` entry.

**Deliberately not used:** `expo-notifications` (it can't show a system-ticked countdown chronometer, and we'd still need native code), AsyncStorage/MMKV (second store breaks atomicity), WorkManager, any foreground service in v1.0, any network library, Redux, analytics/crash SDKs.

`android/` and `ios/` are generated by `npx expo prebuild` and are **not committed**. Every native change goes through a config plugin or the local module.

## 3. Timer state machine (`src/domain/timer`)
States: `IDLE` (prepared, not started) → `RUNNING` ⇄ `PAUSED` → `COMPLETED`; terminal side-exits `CANCELLED` (reset/skip/end) and `INTERRUPTED` (unprovable after reboot).

Pure function, no side effects:
```ts
reduce(state: ActiveTimer, cmd: Command, now: Now, settings: Settings)
  : { next: ActiveTimer; effects: Effect[] }
type Now = { elapsedMs: number; epochMs: number; bootCount: number; tzOffsetMin: number }
type Command = Start | Pause | Resume | Reset | Skip | SetIntent | Reconcile | PrepareNext
type Effect = RecordSession | ScheduleAlarm | CancelAlarm | ShowOngoing | ShowCompletion | ClearNotifications | UpdateWidget
```
Rules:
- Remaining while running = `deadlineElapsedMs - now.elapsedMs`. Never a decrementing counter.
- Pause stores `remainingMs`; resume sets a new deadline = `now.elapsedMs + remainingMs`.
- Every command is idempotent: Pause when paused = no-op; Start when running = no-op; a stale command carrying an old `sessionId` = no-op. Widget/notification commands always carry the `sessionId` they were rendered with.
- `Reconcile` is the only path to COMPLETED. It fires on app foreground, headless alarm task, boot, every command, and the UI tick when remaining ≤ 0.
- Completion produces exactly one `RecordSession` effect for a given session ID.

### Auto-start rules (prevent phantom bubbles)
- Auto-start breaks: a focus→break transition may start the break even while the app is backgrounded; the break's deadline is chained from the focus deadline.
- Auto-start focus after a break: only if the app is in the foreground when the break ends. Otherwise the focus is prepared as IDLE. **The app never starts a focus session the user isn't present for.**
- Reconcile never chains more than one transition per call while backgrounded.

## 4. TimerController (`src/services/TimerController.ts`)
The single authoritative entry point used by screens, headless tasks (widget, notification actions, alarm, boot) and tests.
1. Commands are serialized through a promise-chain mutex (one in flight).
2. For each command: read state + settings inside a SQLite transaction → `reduce` → write `active_timer` and any `sessions` row (`INSERT OR IGNORE`, primary key = session ID) **in the same transaction** → commit → run platform effects (alarms, notifications, widget) → publish the new state to the zustand mirror.
3. Platform effects run after commit and are themselves idempotent (re-scheduling the same alarm ID replaces it). If the process dies between commit and effects, the next Reconcile re-derives and re-applies effects from DB state.

Headless tasks run in the same JS runtime as the app when it's alive, so the mutex covers both.

## 5. Clock model
`focus-native` exposes a **synchronous** `now()` (JSI) returning `SystemClock.elapsedRealtime()`, `System.currentTimeMillis()`, `Settings.Global.BOOT_COUNT` and the current timezone offset. Tests inject a fake.
- Running state persists: `deadlineElapsedMs`, `bootCount`, `startedAtEpochMs`, `durationMs`.
- Reboot: if `now.bootCount !== state.bootCount` (or `now.elapsedMs` is smaller than the session start elapsed), a RUNNING session becomes INTERRUPTED with no bubble. PAUSED sessions are unaffected (they hold `remainingMs`, not a deadline).
- Wall clock is used only to label history (completion time, local date), never to measure duration.
- Completion epoch = `now.epochMs - (now.elapsedMs - deadlineElapsedMs)` so a late reconcile still records the true finish time.

## 6. Native module `focus-native` (Kotlin)
| Capability | Implementation |
|---|---|
| `now()` | Sync function, see §5 |
| Completion alarm | `AlarmManager` on `ELAPSED_REALTIME_WAKEUP`. If `canScheduleExactAlarms()` → `setExactAndAllowWhileIdle`; else `setAndAllowWhileIdle` (may be late in Doze). Manifest declares `SCHEDULE_EXACT_ALARM` only; **not** `USE_EXACT_ALARM` (Play restricts it to alarm-clock/calendar apps). |
| Alarm receiver | Posts the completion notification (text precomputed and passed as extras, so no JS needed), plays sound/vibration per stored settings, updates widget to "Done", then starts headless `Reconcile`. |
| Ongoing notification | `NotificationCompat` with `setUsesChronometer(true)`, `setChronometerCountDown(true)`, `setWhen(deadline as epoch)`, `setOngoing(true)`, `setOnlyAlertOnce(true)`. The system ticks it; the app never posts per-second updates. Actions → `CommandReceiver`. |
| Channels | `running` (IMPORTANCE_LOW, silent) and `alerts` (IMPORTANCE_HIGH, channel sound/vibration **off**; sound and vibration are played by the receiver so the in-app toggles work after channel creation). |
| Sound/vibration | Play only if ringer mode is NORMAL and interruption filter is ALL (respects silent/DND). Vibrate if enabled and ringer ≠ SILENT. Plays even when notifications are denied (decision D-07). |
| Command receiver | Widget and notification buttons → `CommandReceiver` → starts `HeadlessJsTaskService` task `FocusCommand { cmd, sessionId }`. |
| Boot receiver | `RECEIVE_BOOT_COMPLETED` → headless `Reconcile` (marks INTERRUPTED, fixes the widget, which would otherwise show a nonsense chronometer). |
| Widget | Custom `AppWidgetProvider` + `RemoteViews` with a `Chronometer` (count-down) for live time; the progress ring is a bitmap rendered on state change only. JS pushes a snapshot via `updateWidget(json)` (stored in SharedPreferences) and the provider renders from it. While a command is in flight, the button shows "…" and is disabled. |
| Dynamic colours | `getDynamicPalette()` reads `system_accent1_*`/`system_neutral1_*` on API 31+; returns null below. |
| Exact alarm settings | `canScheduleExactAlarms()`, `openExactAlarmSettings()` |

### Risk: headless JS from background broadcasts
Starting `HeadlessJsTaskService` from a widget/notification broadcast relies on the temporary background-start allowance Android grants to user-initiated PendingIntents and `setExactAndAllowWhileIdle` alarms. **This must be proven on a real device in Phase 1b** (API 26, 31 and 34+ behaviour). Acceptance: widget Pause/Resume takes effect within 3 s on a budget phone with the app process dead.
**Fallback if it fails:** port `reduce` to Kotlin for the widget/notification commands only, and keep both implementations honest with shared golden test vectors (`src/domain/timer/__fixtures__/vectors.json`) run by both Jest and JUnit. Record which path was taken in `DECISIONS.md`.

## 7. Persistence
SQLite schema in `DATA_MODEL.md`. Migrations via `PRAGMA user_version`, forward-only, each in a transaction, never destructive. A migration test opens a v1 fixture DB and migrates it.

## 8. Permissions (final manifest must equal this list)
`POST_NOTIFICATIONS`, `SCHEDULE_EXACT_ALARM`, `RECEIVE_BOOT_COMPLETED`, `VIBRATE`, `WAKE_LOCK` (used only by HeadlessJsTaskService for task duration). **`INTERNET` must be removed from release builds** with a config plugin (`tools:node="remove"`); debug builds may keep it for Metro. No `USE_EXACT_ALARM`, no `FOREGROUND_SERVICE*`, no storage, no location, no `QUERY_ALL_PACKAGES`. Release check: `aapt dump permissions` output pasted into `PROGRESS.md`.

## 9. Build pipeline (Claude Code runs in the cloud, no Android SDK)
- Claude Code runs locally in its sandbox: `npm ci`, `npx tsc --noEmit`, `npx eslint .`, `npx jest`, `npx expo prebuild --platform android --no-install` (to validate config plugins), `npx expo-doctor`.
- **Gradle builds run in GitHub Actions** (`ubuntu-latest` ships the Android SDK): prebuild → `./gradlew testDebugUnitTest lintDebug assembleDebug`. Claude Code triggers and reads runs with `gh run watch` / `gh run view --log-failed`.
- Phase builds: pushing a tag `phase-N` publishes a GitHub **pre-release** with `FocusBubble-phase-N-debug.apk` so it can be downloaded straight to the phone.
- Release builds: `bundleRelease` signed with an upload key stored in GitHub Secrets (`RELEASE.md`). EAS Build is an optional alternative; its free tier has a monthly build quota, so don't make it the only path.
- If the sandbox can't reach GitHub or npm, Claude Code stops and reports the exact error; it never claims a build.

## 10. Testability
Pure domain = unit tests with a fake clock. Controller = tests with in-memory SQLite (or a repository fake) + fake platform. Native module = JUnit for receivers' pure logic (snapshot → RemoteViews model, sound-gating rules). Device behaviour = manual checklist on your phone (`QA_TEST_PLAN.md`).
